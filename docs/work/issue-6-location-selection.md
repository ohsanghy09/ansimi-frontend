# feat: 지도 및 주소 검색 기반 출발지·도착지 설정 기능 구현

[문서 목록으로 돌아가기](../README.md)

## 작업 목적과 범위

출발·도착 카드를 클릭하여 지도 중앙 마커 또는 주소·장소 검색으로 위치를 선택하고, 확정한 주소를 카드에 반영한다. 두 위치는 동일한 선택 흐름을 사용한다.

- 관련 이슈: #6
- 작업 브랜치명: `feat/#6`
- 현재 구현 위치: [src/examples/ExamplePage.tsx](../../src/examples/ExamplePage.tsx)
- 확인 경로: 개발 서버의 `/example`
- 현재 단계: 예제 구현 완료, 실제 브라우저 검증 및 메인 화면 적용 전

이번 예제는 `ExamplePage.tsx` 안에서 구현했다. `App.tsx`, `MainPage.tsx`, `LocationCard.tsx`, `KaKaoMap.tsx`에 해당 기능을 적용하는 작업은 포함하지 않았다. 현재 위치 자동 설정, 경로 탐색, 안전도 평가도 이번 작업 범위에 포함하지 않는다.

기존 기획은 출발지를 현재 위치로 사용하지만, 이번 흐름은 사용자가 출발지도 직접 지정할 수 있도록 확장한 것이다. 실제 귀가 시작 시 현재 위치와 지정한 출발지가 다른 경우의 처리는 추후 정해야 한다.

## 사용자 흐름

### 1. 출발지 또는 도착지 선택 시작

1. 출발 또는 도착 카드를 클릭한다.
2. 선택한 카드의 테두리와 배경색을 변경하여 현재 선택 대상을 표시한다.
3. 해당 위치의 주소·장소 검색창을 표시한다.
4. 지도 중앙에 고정 마커를 표시한다.
5. 지도에 대상에 맞는 안내 문구를 표시한다.
   - 출발: “지도를 움직여 출발 위치를 선택해주세요!”
   - 도착: “지도를 움직여 도착 위치를 선택해주세요!”
6. 하단에 선택 중인 출발지·도착지 카드와 취소·설정 버튼을 표시한다.

### 2. 지도 이동으로 위치 선택

중앙 마커는 고정하고 지도를 움직여 위치를 선택한다. 지도 중심의 좌표를 후보 위치로 사용한다.

| 상태 | 하단 주소 영역 | 설정 버튼 |
| --- | --- | --- |
| 지도 이동 중 | 지도를 움직여 위치를 맞춰주세요. | 비활성화 |
| 이동 종료 후 주소 조회 중 | 주소를 확인하고 있습니다… | 비활성화 |
| 주소 조회 성공 | 선택한 위치의 주소 | 활성화 |
| 주소 조회 실패 또는 시간 초과 | 실패·재시도 안내 | 비활성화 |

이전에 조회한 주소가 있어도 지도를 움직이는 즉시 후보를 무효화한다. 도로명주소가 있으면 우선 사용하고, 없으면 지번주소를 사용한다.

### 3. 주소·장소 검색으로 위치 선택

1. 검색창에 포커스하면 입력 영역을 강조한다.
2. 주소 또는 장소 이름을 입력하고 검색 버튼이나 Enter 키로 검색한다.
3. 검색창 아래에 검색 결과 개수와 목록을 표시한다.
4. 결과를 클릭하면 선택한 주소 또는 장소 이름을 검색창에 표시한다.
5. 해당 좌표로 지도를 이동하고 중앙 위치의 주소를 조회한다.
6. 조회한 주소를 하단 선택 카드에 표시한다.
7. 필요하면 지도를 움직여 위치를 추가로 조정한다.

검색 영역과 결과 카드는 부모 컨테이너의 가로 폭을 채운다. 현재 예제의 부모 컨테이너에는 `max-w-2xl` 제한이 있으므로 브라우저 전체 너비를 채우는 구조는 아니다.

### 4. 확정 또는 취소

- “이 위치로 출발지 설정” 또는 “이 위치로 도착지 설정” 버튼으로 좌표와 주소를 확정한다.
- 확정한 주소를 상단의 해당 카드에 반영하고 선택 모드를 종료한다.
- 확정된 위치에는 지도 좌표에 연결된 마커를 남긴다.
- 확정 전까지 상단 카드의 기존 주소는 유지한다.
- 취소하면 기존 출발지·도착지를 유지하고 선택 모드를 종료한다.
- 이미 설정한 카드를 다시 선택하면 저장된 좌표로 지도를 이동하여 수정할 수 있다.

## 구현 내용

### 상태 관리

| 상태 | 용도 |
| --- | --- |
| `mode` | 출발지 선택, 도착지 선택, 선택 종료 구분 |
| `locations` | 확정된 출발지·도착지의 좌표와 주소 |
| `candidate` | 현재 선택 중인 좌표와 주소 |
| `message` | 지도 이동·주소 조회 상태 안내 |
| `query` | 검색창 입력값 |
| `searchResults` | 주소·장소 검색 결과 |
| `searchMessage`, `searching` | 검색 안내와 진행 여부 |

후보와 확정 위치를 분리하여 지도 이동이나 검색만으로 기존 카드 주소가 바뀌지 않도록 한다.

### 카카오 SDK 연결

- `services` 라이브러리를 포함하여 SDK를 불러온다.
- `center_changed`, `zoom_start`에서 이전 후보를 무효화한다.
- `idle`에서 지도 중앙 좌표를 읽고 `coord2Address`로 주소를 조회한다.
- `addressSearch`와 `keywordSearch` 결과를 합치고 동일 좌표의 중복을 제거한다.
- 검색 결과 선택 시 `setCenter`로 이동하고 주소를 다시 조회한다.
- 같은 중심 좌표를 선택해도 주소를 조회하도록 `idle` 이벤트를 명시적으로 발생시킨다.

검색은 주소와 장소를 각각 최대 5개 요청한다. 표시하는 결과 개수는 두 응답을 합쳐 중복을 제거한 목록의 개수이며, 전체 검색 결과의 총개수는 아니다. 현재 페이지 이동은 구현하지 않았다.

### 비동기 및 오류 처리

- 지도 이동·주소 조회 중에는 설정 버튼을 비활성화한다.
- 이전 좌표의 주소 응답이 최신 후보를 덮어쓰지 않게 요청 식별값으로 확인한다.
- 검색어 변경, 선택 대상 변경, 취소, 확정, 화면 이탈 시 이전 검색 응답을 무효화한다.
- 빈 검색어, 검색 결과 없음, 검색 실패, 주소 조회 실패를 구분하여 안내한다.
- 검색 및 좌표의 주소 조회 제한 시간은 각각 10초다.
- 지도 로딩이 15초 이상 지연되면 설정 확인과 새로고침을 안내한다.
- 화면 이탈 시 이벤트 리스너, 타이머, 생성한 마커 등을 정리한다.

## 실행 및 확인 방법

1. 프로젝트 루트의 `.env.local`에 `VITE_KAKAO_MAP_KEY`를 설정한다.
2. 카카오 개발자 설정에 개발 서버의 도메인을 등록한다.
3. `npm run dev`를 실행한다. 환경변수를 바꿨다면 서버를 재시작한다.
4. 터미널에 표시된 개발 서버 주소에 `/example`을 붙여 접속한다.
5. 지도 선택과 검색 선택을 출발지·도착지에 각각 시도한다.

## 검증 현황 및 남은 작업

예제 구현 후 `npm run build`와 `npm run lint`는 통과했다. 실제 브라우저에서 카카오 지도·검색 API의 정상 동작과 모바일 사용성은 아직 확인하지 않았다.

### 브라우저 검증 항목

- [ ] 출발·도착 선택 시 카드 강조, 안내 문구, 마커 색상이 일치한다.
- [ ] 지도를 움직이는 즉시 하단 문구가 변경되고 설정 버튼이 비활성화된다.
- [ ] 주소 조회가 완료된 뒤에만 위치를 확정할 수 있다.
- [ ] 검색창 포커스 표시와 검색 결과 개수·목록이 정상적으로 보인다.
- [ ] 주소와 장소 이름을 각각 검색하고 결과를 선택할 수 있다.
- [ ] 선택 결과가 검색창, 지도 중심, 하단 주소에 올바르게 반영된다.
- [ ] 검색 후 지도를 다시 움직여 위치를 조정할 수 있다.
- [ ] 확정 시 해당 카드만 갱신되고 취소 시 기존 주소가 유지된다.
- [ ] 빠른 지도 이동·재검색·선택 대상 변경 시 오래된 응답이 반영되지 않는다.
- [ ] 검색 결과 없음, 네트워크 실패, 시간 초과 상황을 확인한다.
- [ ] 모바일 키보드가 열린 상태에서 검색과 결과 선택이 가능하다.

### 후속 작업

- [ ] 고정 높이·비율의 지도 대신 남은 공간을 채우는 레이아웃 적용 검토
- [ ] 작은 화면에서 카드·검색 결과·확정 버튼의 배치와 스크롤 검증
- [ ] 검증한 예제 흐름을 메인 화면에 적용
- [ ] 현재 위치 기본 설정 및 수동 출발지 선택 정책 확정
- [ ] 확정한 좌표를 백엔드 경로 요청과 연결

현재 예제 지도는 `h-[50dvh] min-h-72`를 사용한다. 카드와 검색 결과 높이가 더해져 세로 스크롤이 생길 수 있으며, 한 화면 안에 맞추는 레이아웃은 아직 적용하지 않았다.
