# feat: 지도 및 주소 검색 기반 출발지·도착지 설정 기능 구현

[문서 목록으로 돌아가기](../README.md)

## 작업 목적과 범위

출발·도착 카드를 클릭하여 지도 중앙 마커 또는 주소·장소 검색으로 위치를 선택하고, 확정한 주소를 카드에 반영한다. 두 위치는 동일한 선택 흐름을 사용한다.

- 관련 이슈: #6
- 작업 브랜치명: `feat/#6`
- 현재 구현 위치: [src/examples/ExamplePage.tsx](../../src/examples/ExamplePage.tsx)
- 확인 경로: 개발 서버의 `/example`
- 현재 단계: 지도 선택 안내·중앙 마커·후보 주소 조회 및 확정 연결 완료, 실제 브라우저 검증 전

이번 예제는 `ExamplePage.tsx` 안에서 구현했다. `App.tsx`, `MainPage.tsx`, `LocationCard.tsx`, `KaKaoMap.tsx`에 해당 기능을 적용하는 작업은 포함하지 않았다. 현재 위치 자동 설정, 경로 탐색, 안전도 평가도 이번 작업 범위에 포함하지 않는다.

기존 기획은 출발지를 현재 위치로 사용하지만, 이번 흐름은 사용자가 출발지도 직접 지정할 수 있도록 확장한 것이다. 실제 귀가 시작 시 현재 위치와 지정한 출발지가 다른 경우의 처리는 추후 정해야 한다.

## 사용자 흐름

### 1. 출발지 또는 도착지 선택 시작

1. 출발 또는 도착 카드를 클릭한다.
2. 선택한 카드의 테두리와 배경색을 변경하여 현재 선택 대상을 표시한다.
3. 해당 위치의 주소·장소 검색창을 표시한다.
4. 지도 중앙에 고정 마커를 표시한다.
5. 지도에 대상에 맞는 안내 문구를 표시한다.
   - 출발: “지도를 움직여 출발 위치를 선택해주세요!”
   - 도착: “지도를 움직여 도착 위치를 선택해주세요!”
6. 하단에 선택 중인 출발지·도착지 카드와 취소·설정 버튼을 표시한다.

### 2. 지도 이동으로 위치 선택

중앙 마커는 고정하고 지도를 움직여 위치를 선택한다. 지도 중심의 좌표를 후보 위치로 사용한다.

| 상태 | 하단 주소 영역 | 설정 버튼 |
| --- | --- | --- |
| 지도 이동 중 | 지도를 움직여 위치를 맞춰주세요. | 비활성화 |
| 이동 종료 후 주소 조회 중 | 주소를 확인하고 있습니다… | 비활성화 |
| 주소 조회 성공 | 선택한 위치의 주소 | 활성화 |
| 주소 조회 실패 또는 시간 초과 | 실패·재시도 안내 | 비활성화 |

이전에 조회한 주소가 있어도 지도를 움직이는 즉시 후보를 무효화한다. 도로명주소가 있으면 우선 사용하고, 없으면 지번주소를 사용한다.

### 3. 주소·장소 검색으로 위치 선택

1. 검색창에 포커스하면 입력 영역을 강조한다.
2. 주소 또는 장소 이름을 입력하고 검색 버튼이나 Enter 키로 검색한다.
3. 검색창 아래에 검색 결과 개수와 목록을 표시한다.
4. 결과를 클릭하면 선택한 주소 또는 장소 이름을 검색창에 표시한다.
5. 해당 좌표로 지도를 이동하고 중앙 위치의 주소를 조회한다.
6. 조회한 주소를 하단 선택 카드에 표시한다.
7. 필요하면 지도를 움직여 위치를 추가로 조정한다.

검색 영역과 결과 카드는 부모 컨테이너의 가로 폭을 채운다. 현재 예제의 부모 컨테이너에는 `max-w-2xl` 제한이 있으므로 브라우저 전체 너비를 채우는 구조는 아니다.

### 4. 확정 또는 취소

- “이 위치로 출발지 설정” 또는 “이 위치로 도착지 설정” 버튼으로 좌표와 주소를 확정한다.
- 확정한 주소를 상단의 해당 카드에 반영하고 선택 모드를 종료한다.
- 확정된 위치에는 지도 좌표에 연결된 마커를 남긴다.
- 확정 전까지 상단 카드의 기존 주소는 유지한다.
- 취소하면 기존 출발지·도착지를 유지하고 선택 모드를 종료한다.
- 이미 설정한 카드를 다시 선택하면 저장된 좌표로 지도를 이동하여 수정할 수 있다.

## 구현 내용

### 출발·도착 카드 선택 및 강조 예제

[ExampleComponent.tsx](../../src/examples/ExampleComponent.tsx)는 기존 `LocationCard.tsx`의 디자인을 바탕으로 카드 선택과 강조 표시를 구현한 별도 예제다. 안심이 제목, 버튼 크기, 문구, 출발·도착 점의 색상을 유지했다. 이 컴포넌트 자체에는 지도나 주소 검색 기능을 연결하지 않았다.

#### 선택 상태와 클릭 동작

`searchType`으로 현재 선택 대상을 관리한다.

```tsx
const [searchType, setSearchType] = useState<'start' | 'end' | null>(null)
```

| 값 | 의미 |
| --- | --- |
| `null` | 선택 없음 |
| `'start'` | 출발 선택 |
| `'end'` | 도착 선택 |

출발 버튼의 클릭 처리는 다음과 같다. 도착 버튼은 `'start'` 대신 `'end'`를 사용한다.

```tsx
onClick={() => setSearchType(searchType === 'start' ? null : 'start')}
```

- 선택하지 않은 버튼을 누르면 해당 버튼을 선택한다.
- 같은 버튼을 다시 누르면 선택을 해제한다.
- 다른 버튼을 누르면 선택을 전환한다.

클릭 시 `onClick`에서 상태 변경을 요청하고, 다시 렌더링하면서 `className`이 새 상태에 맞는 스타일을 적용한다. 현재 예제에서는 `aria-pressed`를 제외했으며, 선택 강조는 `searchType`과 `className`으로 처리한다.

#### 공통 스타일과 조건부 스타일

JSX의 바깥 `{}` 안에 JavaScript 표현식을 작성한다. 백틱으로 문자열을 만들고 `${}` 안에 조건에 따른 스타일을 넣어 공통 스타일과 합친다.

```tsx
className={`flex h-12 w-full items-center rounded-xl border-2 px-3 text-left ${
  searchType === 'start'
    ? 'border-[#25A77A] bg-[#EDF8F2]'
    : 'border-transparent bg-[#F4F7F2]'
}`}
```

| 상태 | 테두리 | 배경 |
| --- | --- | --- |
| 선택 | `border-[#25A77A]` 초록색 | `bg-[#EDF8F2]` 연한 초록색 |
| 미선택 | `border-transparent` 투명 | `bg-[#F4F7F2]` 기존 배경 |

`border-2`는 공통으로 적용하고 테두리 색만 변경한다. `border-transparent`는 테두리를 제거하지 않고 투명하게 표시하므로, 선택·해제할 때 테두리 공간이 유지되고 내부 글자나 점이 밀리지 않는다.

### 카드 선택 시 검색 컴포넌트 표시

`ExampleComponent.tsx`에는 출발·도착 카드 아래에 검색 UI를 보여주는 `LocationSearch` 함수를 추가했다. 이 파일 안의 검색 UI와 별도 파일인 `src/components/location/LocationSearch.tsx`는 현재 각각 존재하며, 예제가 별도 파일을 import하는 구조로 변경하지는 않았다.

```tsx
{searchType && (
  <LocationSearch key={searchType} searchType={searchType} />
)}
```

- `searchType`이 `null`이면 검색 컴포넌트를 표시하지 않는다.
- `'start'` 또는 `'end'`이면 검색 컴포넌트를 표시하고 선택 대상을 전달한다.
- 이 코드를 출발·도착 카드 다음에 배치하여 검색 UI가 카드 하단에 나타나게 한다.
- 같은 카드를 다시 누르면 선택이 해제되어 검색 UI도 사라진다.
- `key`가 바뀌면 React가 기존 검색 컴포넌트를 제거하고 새로 생성하여 내부 검색어와 안내 상태를 초기화한다.
- `key`는 React가 사용하는 특별한 속성이므로 함수의 일반 props로 전달되지 않는다. 선택 대상은 `searchType` 속성으로 전달한다.

### 별도 주소·장소 검색 카드 컴포넌트

[LocationSearch.tsx](../../src/components/location/LocationSearch.tsx)에 실제 화면에서 사용할 검색 카드 UI를 작성했다. 출발지·도착지 제목, 입력창, 검색 버튼, 안내 문구와 입력창 선택 시 초록색 강조를 제공한다.

| props | 역할 |
| --- | --- |
| `searchType` | 필수 값. `'start'`이면 출발지, `'end'`이면 도착지 제목 표시 |
| `onSearch` | 선택 값. 입력한 검색어를 전달받는 부모의 함수 |

```tsx
type LocationSearchProps = {
  searchType: 'start' | 'end'
  onSearch?: (query: string) => void
}
```

`query` 상태는 입력값을, `message` 상태는 입력창 아래 안내를 관리한다. 입력은 최대 100자로 제한한다.

검색 버튼 클릭과 Enter 입력은 모두 `handleSubmit`으로 처리한다.

1. `event.preventDefault()`로 폼 제출에 따른 페이지 이동을 막는다.
2. `trim()`으로 검색어 앞뒤 공백을 제거한다.
3. 빈 검색어면 입력 안내를 표시하고 중단한다.
4. `onSearch`가 없으면 “검색 기능은 준비 중입니다.”를 표시한다.
5. 함수가 있으면 안내를 지우고 `onSearch(keyword)`로 검색어를 전달한다.

이 컴포넌트는 카카오 검색 API를 직접 호출하지 않는다. 실제 검색 결과 목록, 결과 개수, 지도 이동, 위치 확정은 아직 연결하지 않았다. `ExamplePage.tsx`의 검색 기능과 구분한다.

#### 가독성을 위한 코드 정리

- `props`로 객체를 받은 뒤 `props.searchType`, `props.onSearch`를 각각 변수로 꺼낸다.
- 출발지·도착지 제목은 `if`문으로 결정한다.
- 입력 변경은 `handleChange`, 폼 제출은 `handleSubmit`으로 분리한다.
- JSX에는 `onChange={handleChange}`, `onSubmit={handleSubmit}`처럼 연결만 작성한다.
- 이벤트 타입은 `ChangeEvent<HTMLInputElement>`, `FormEvent<HTMLFormElement>`로 지정한다.
- 타입, 상태, 검색 처리, 화면 요소에 역할을 설명하는 주석을 작성했다.

정리 전후의 기능과 디자인은 동일하다. 별도 검색 카드 작성 및 가독성 정리 후 `npm run build`와 `npm run lint`가 통과했다.

#### MainPage 연결 방향

연결 시 `searchType`을 `MainPage`에서 관리하고 `LocationCard`에 선택 상태와 변경 함수를 전달한다. `LocationCard` 클릭으로 부모 상태를 바꾸고, `MainPage`에서 카드 아래에 검색 컴포넌트를 조건부로 표시한다.

```tsx
{searchType && (
  <LocationSearch key={searchType} searchType={searchType} />
)}
```

이 예시는 부모에서 상태와 import를 준비한 뒤 사용할 연결 방식이다. 이번 작업에서는 별도 검색 컴포넌트를 `MainPage`에 연결하지 않았다.

### ExamplePage의 상태 관리

| 상태 | 용도 |
| --- | --- |
| `mode` | 출발지 선택, 도착지 선택, 선택 종료 구분 |
| `locations` | 확정된 출발지·도착지의 좌표와 주소 |
| `candidate` | 현재 선택 중인 좌표와 주소 |
| `message` | 지도 이동·주소 조회 상태 안내 |
| `query` | 검색창 입력값 |
| `searchResults` | 주소·장소 검색 결과 |
| `searchMessage`, `searching` | 검색 안내와 진행 여부 |

후보와 확정 위치를 분리하여 지도 이동이나 검색만으로 기존 카드 주소가 바뀌지 않도록 한다.

### 카카오 SDK 연결

- `services` 라이브러리를 포함하여 SDK를 불러온다.
- `center_changed`, `zoom_start`에서 이전 후보를 무효화한다.
- `idle`에서 지도 중앙 좌표를 읽고 `coord2Address`로 주소를 조회한다.
- `addressSearch`와 `keywordSearch` 결과를 합치고 동일 좌표의 중복을 제거한다.
- 검색 결과 선택 시 `setCenter`로 이동하고 주소를 다시 조회한다.
- 같은 중심 좌표를 선택해도 주소를 조회하도록 `idle` 이벤트를 명시적으로 발생시킨다.

검색은 주소와 장소를 각각 최대 5개 요청한다. 표시하는 결과 개수는 두 응답을 합쳐 중복을 제거한 목록의 개수이며, 전체 검색 결과의 총개수는 아니다. 현재 페이지 이동은 구현하지 않았다.

### 비동기 및 오류 처리

- 지도 이동·주소 조회 중에는 설정 버튼을 비활성화한다.
- 이전 좌표의 주소 응답이 최신 후보를 덮어쓰지 않게 요청 식별값으로 확인한다.
- 검색어 변경, 선택 대상 변경, 취소, 확정, 화면 이탈 시 이전 검색 응답을 무효화한다.
- 빈 검색어, 검색 결과 없음, 검색 실패, 주소 조회 실패를 구분하여 안내한다.
- 검색 및 좌표의 주소 조회 제한 시간은 각각 10초다.
- 지도 로딩이 15초 이상 지연되면 설정 확인과 새로고침을 안내한다.
- 화면 이탈 시 이벤트 리스너, 타이머, 생성한 마커 등을 정리한다.

## 합의한 컴포넌트 분리 설계

`ExamplePage.tsx`에 모여 있는 기능을 역할별로 분리하고, 기존 `MainPage.tsx` 안에서 동일하게 동작하도록 연결한다. 별도 `LocationSelectPage.tsx`나 라우트는 추가하지 않는다. 출발·도착 선택부터 검색, 지도 이동, 위치 확정까지 화면 전환 없이 메인 화면에서 처리한다.

### 폴더 구조

```text
src/
├─ components/
│  ├─ location/
│  │  ├─ LocationCard.tsx       # 출발·도착 카드
│  │  ├─ LocationSearch.tsx     # 검색 입력과 결과 목록
│  │  └─ LocationConfirm.tsx    # 선택 주소 확인·취소·확정
│  └─ KaKaoMap.tsx              # 지도·안내 문구·마커
├─ hooks/
│  └─ useLocationSearch.ts      # 주소·장소 검색 로직
├─ types/
│  └─ location.ts               # 공통 위치 데이터 타입
├─ pages/
│  └─ MainPage.tsx              # 전체 상태 관리와 컴포넌트 연결
├─ examples/
│  └─ ExamplePage.tsx           # 기존 동작 참고용 예제
└─ App.tsx                     # 기존 라우팅
```

위 트리는 이번 설계와 관련된 파일만 표시한다. `ExampleComponent.tsx` 등 기존의 다른 파일도 유지한다.

### 파일별 역할과 상태 관리

| 파일 | 구현할 역할 |
| --- | --- |
| `MainPage.tsx` | 선택 대상, 후보 위치, 확정된 출발·도착 위치를 관리하고 자식 컴포넌트에 값과 이벤트 함수를 전달한다. |
| `LocationCard.tsx` | 출발·도착 버튼, 선택 강조, 확정된 주소를 표시하고 선택 이벤트를 부모에 전달한다. |
| `LocationSearch.tsx` | 검색 입력, 검색 중·실패·결과 없음 안내, 결과 목록을 표시하고 검색 및 결과 선택 이벤트를 전달한다. |
| `LocationConfirm.tsx` | 선택 중인 출발지·도착지의 후보 주소와 조회 상태, 취소·확정 버튼을 표시한다. 후보가 유효할 때만 확정할 수 있게 한다. |
| `KaKaoMap.tsx` | 지도를 표시하고 검색 결과 좌표로 이동한다. 지도 중심 주소 조회, 선택 대상별 안내 문구, 중앙 고정 마커, 확정 위치 마커를 담당한다. |
| `useLocationSearch.ts` | 카카오 주소·장소 검색을 함께 실행하고 결과 병합·중복 제거, 검색 상태·안내, 시간 초과 및 오래된 응답 무효화를 처리한다. |
| `location.ts` | 여러 파일이 공유하는 위치 관련 데이터 타입을 정의한다. |

`LocationCard`, `LocationSearch`, `LocationConfirm`은 같은 위치 선택 기능이므로 `components/location`에 모은다. `KaKaoMap`은 다른 화면에서도 사용할 수 있도록 별도로 둔다.

공유 상태는 `MainPage`에서 관리한다. 검색 결과·검색 중 여부·검색 안내는 `useLocationSearch`가 관리하고 필요한 값과 함수를 페이지에 반환한다. 각 컴포넌트만 사용하는 입력 상태나 props 타입은 해당 파일에 둘 수 있다.

### 검색 훅과 지도 기능의 구분

`useLocationSearch.ts`는 주소·장소 검색을 담당하는 커스텀 훅이다. 카카오 SDK가 준비된 뒤 검색 기능을 전달받아 실행하는 구조로 설계한다. 검색 결과에는 장소 이름, 주소, 위도·경도가 포함된다.

1. `LocationSearch`에서 검색어를 입력하고 검색한다.
2. `MainPage`가 훅의 검색 함수를 호출한다.
3. 훅이 주소 검색과 장소 검색 결과를 합쳐 반환한다.
4. `LocationSearch`가 결과 목록을 표시한다.
5. 결과를 선택하면 `MainPage`가 좌표를 `KaKaoMap`에 전달한다.
6. 지도가 해당 좌표로 이동하고 중심 주소를 조회하여 후보 위치를 갱신한다.

주소는 검색 목록에 표시하고 좌표는 지도 이동에 사용한다. 지도를 직접 움직였을 때 중심 좌표를 주소로 바꾸는 처리는 검색 훅이 아닌 지도 쪽에서 담당한다. SDK 로딩은 검색과 지도가 함께 사용할 수 있도록 공통으로 관리할 예정이다. 로더의 파일 위치는 아직 확정하지 않았다.

### 공통 타입의 의미

`types/location.ts`는 실제 위치 값을 저장하는 파일이 아니다. 데이터의 형태를 한곳에 정의하여 여러 파일에서 같은 타입 선언을 반복하지 않도록 한다. 다음 네 가지 타입을 작성하고 각 항목의 의미를 주석으로 추가했다.

| 타입 | 의미 |
| --- | --- |
| `LocationType` | `'start'` 또는 `'end'`로 출발·도착 구분 |
| `Location` | `latitude`, `longitude`, `address`를 가진 위치 정보 |
| `SearchResult` | 위치 정보에 장소 이름인 `name`을 추가한 검색 결과 |
| `SelectedLocations` | 출발·도착 각각의 확정 위치. 선택 전에는 `null` |

타입 공유와 상태 공유는 다르다. `location.ts`가 데이터 형태를 정의하고, `MainPage`가 실제 후보·확정 위치 값을 상태로 보관하여 컴포넌트에 전달한다.

### 메인 화면에서의 연결 흐름

1. 출발·도착 카드를 누르면 해당 대상을 강조하고 검색 및 위치 확인 영역을 표시한다. 기존 확정 위치가 있으면 지도를 그 위치로 이동한다.
2. 검색 결과를 선택하거나 지도를 직접 움직여 후보 위치를 정한다.
3. 지도에는 “지도를 움직여 출발 위치를 선택해주세요.” 또는 “지도를 움직여 도착 위치를 선택해주세요.” 문구와 중앙 선택 마커를 표시한다.
4. 중심 주소 조회 결과를 `LocationConfirm`에 표시한다. 이동·조회 중에는 후보를 무효화하고 확정 버튼을 비활성화한다.
5. 확정하면 해당 출발·도착 위치를 저장하고 카드 주소와 지도 마커를 갱신한다.
6. 취소하면 후보만 버리고 기존 확정 주소를 유지한다.

### 현재 파일 정리 완료 범위

사용자 요청에 따라 기능 구현에 앞서 폴더 구조와 파일별 역할 주석만 준비했다.

- 기존 `LocationCard.tsx`, `LocationSearch.tsx`를 `components/location/`으로 이동하고 기존 코드를 유지했다.
- 이동한 `LocationCard`를 사용하는 `MainPage.tsx`, `App.tsx`의 import 경로를 수정했다.
- `LocationConfirm.tsx`, `useLocationSearch.ts`, `types/location.ts`를 생성했다. 이후 `types/location.ts`에는 공통 타입을 작성했고, 나머지 두 파일에는 아직 역할 주석만 있다.
- 구조에 포함된 기존 파일의 맨 위에도 역할 주석을 추가했다. 주석은 구현할 책임을 나타내며 모든 기능이 이미 완성되었다는 뜻은 아니다.
- `MainPage`의 공유 상태 관리, 실제 검색 연결, 지도 선택 기능, 위치 확정 기능은 아직 적용하지 않았다.
- 대화에서 제시한 검색 훅·컴포넌트 props 코드는 설명용 예시이며 아직 구현하지 않았다. 공통 타입 네 가지는 아래 내용으로 작성했다.

### 공통 타입 작성 완료

[location.ts](../../src/types/location.ts)에 다음 타입을 `export type`으로 정의했다.

- `LocationType`: `'start' | 'end'`로 출발지·도착지를 구분한다.
- `Location`: 숫자형 `latitude`, `longitude`와 문자열 `address`를 정의한다. 후보 위치와 확정 위치에 공통으로 사용한다.
- `SearchResult`: `Location`에 문자열 `name`을 추가한다. 장소 이름 또는 주소를 검색 결과의 표시 이름으로 사용한다.
- `SelectedLocations`: `Record<LocationType, Location | null>`로 출발·도착 키를 모두 정의한다. 아직 확정하지 않은 위치는 `null`이다.

이번 변경은 타입 정의와 설명 주석 작성까지다. 기존 컴포넌트의 로컬 타입을 교체하거나 `MainPage`에 상태·이벤트를 연결하는 작업은 아직 진행하지 않았다.

검증: `./node_modules/.bin/tsc.cmd -b` 실행 결과 TypeScript 검사가 통과했다. 런타임 동작 변경은 없다. 다음 작업은 공통 타입을 사용하여 `MainPage`의 공유 상태를 구성하고 각 컴포넌트를 연결하는 것이다.

### MainPage 공유 상태와 이벤트 연결 완료

`MainPage`에서 공통 타입을 사용하여 `searchType`, `locations`, `candidate`를 관리한다. `LocationCard`는 내부 선택 상태를 제거하고 부모가 전달하는 선택 상태·확정 주소를 표시하며 클릭 이벤트를 전달하도록 변경했다.

- 카드 클릭 시 같은 메인 화면에서 `LocationSearch`, `LocationConfirm`을 표시한다.
- 같은 카드를 다시 누르거나 취소하면 선택을 종료하고 후보를 지운다. 기존 확정 위치는 유지한다.
- 다른 카드를 누르면 선택 대상을 변경한다. 검색 컴포넌트의 `key` 변경으로 입력값과 안내를 초기화한다.
- 확인 컴포넌트는 후보 주소 및 취소·확정 버튼을 표시한다. 후보가 없으면 확정 버튼을 비활성화한다.
- 확정 이벤트는 후보가 있을 때 해당 위치만 저장하도록 부모에 연결했다.
- `/card` 확인 화면은 `App.tsx`의 `LocationCardPreview`가 선택 상태를 전달한다.

현재 검색 API와 지도 중심 주소 조회는 연결하지 않았으므로 후보는 아직 생성되지 않는다. 검색 시 준비 중 안내가 표시되고 확정 버튼은 비활성 상태다. `KaKaoMap`은 기존처럼 표시하며 지도 이동 이벤트·후보 갱신·마커·안내 문구 연결은 다음 단계에서 구현한다. 앞선 절의 미구현 설명은 각 작업 당시 기록이며 이 절이 최신 연결 상태다.

검증: `npm.cmd run build`, `npm.cmd run lint` 통과. 실제 브라우저의 카드 클릭 및 카카오 API 연동 검증은 아직 수행하지 않았다.

### 주소·장소 검색과 지도 이동 구현 완료

- `lib/kakaoMaps.ts`에 검색·지도 공통 SDK 타입과 로더를 추가했다. `services`를 포함해 한 번 로딩하고, 키 누락·로딩 실패·15초 시간 초과 안내를 제공한다. React 개발 모드의 재마운트에서도 진행 중인 SDK 로딩을 공유한다.
- `useLocationSearch.ts`에서 주소·장소를 각각 최대 5개 검색하고 좌표 중복을 제거한다. 결과 개수는 합쳐진 목록의 개수다. 결과 없음·일부 실패·전체 실패·10초 시간 초과를 구분한다.
- 검색어 변경, 선택 대상 변경, 결과 선택, 취소·확정, 화면 이탈 시 이전 검색 응답을 무효화한다.
- `LocationSearch`에 검색 진행 상태와 결과 목록을 연결했다. 검색 버튼과 Enter로 검색하고 결과 선택 시 표시 이름을 입력창에 반영한다. 지도 준비 전과 검색 중에는 검색 버튼을 비활성화한다.
- `MainPage`가 SDK 준비 상태와 지도 이동 대상인 `mapTarget`을 관리한다. 검색 결과 선택 시 지도에 새 위치 객체를 전달한다.
- `KaKaoMap`은 전달받은 좌표로 중심을 이동한다. 같은 결과를 다시 선택해도 새 객체를 전달하여 이동하도록 했다. 저장된 위치가 있으면 카드 재선택 시 그 위치로 이동한다.

이번 단계에서는 검색 결과를 후보 위치로 바로 확정하지 않는다. 지도 중심 주소 조회, 중앙 선택 마커와 안내 문구, 확정 위치 마커는 다음 단계다. 따라서 `LocationConfirm`의 확정 버튼은 아직 비활성 상태다.

검증: `npm.cmd run build`, `npm.cmd run lint` 통과.

브라우저 확인 시 `/`에서 출발·도착 카드 선택 후 주소와 장소 이름을 각각 검색하고, 결과 선택 시 입력창 이름과 지도 중심이 바뀌는지 확인한다. 빠른 재검색·선택 대상 변경·취소 시 이전 결과가 되살아나지 않는지도 확인한다. 실제 카카오 API 동작은 브라우저 검증 전이다.

### 지도 선택과 후보 주소 조회 구현 완료

`MainPage`가 선택 대상과 확정 위치, 후보 변경 및 주소 조회 안내 콜백을 `KaKaoMap`에 전달한다. `LocationConfirm`에는 실제 후보 주소와 조회 안내를 전달하며 준비 중 문구를 제거했다.

- 선택 모드에서만 “지도를 움직여 출발/도착 위치를 선택해주세요.” 문구와 중앙 고정 마커를 표시한다. 출발은 초록색, 도착은 짙은 초록색으로 구분한다.
- `center_changed`, `zoom_start`에서 이전 요청을 무효화하고 후보를 지워 확정 버튼을 비활성화한다.
- `idle`에서 지도 중심 좌표를 읽고 `coord2Address`로 주소를 조회한다. 도로명주소를 우선하며 없으면 지번주소를 사용한다.
- 주소 조회 성공 시 후보의 좌표·주소를 갱신하고 확인 영역의 확정 버튼을 활성화한다.
- 조회 실패·예외·10초 시간 초과는 재시도 안내를 표시한다. 후보는 비어 있는 상태로 유지한다.
- 선택 시작, 검색 결과 선택, 선택 대상 변경 시 중심 주소를 조회한다. 동일 좌표를 재선택해도 조회한다.
- 선택 종료·대상 변경·새 검색 결과 선택·화면 이탈 시 이전 주소 조회 응답을 무시하고 이벤트 리스너와 타이머를 정리한다.
- 기존 확정 이벤트와 연결하여 확정 주소를 해당 카드에 반영하고 지도에 확정 마커를 표시한다. 취소 시 기존 확정 위치를 유지한다.
- `/map`에서는 선택 관련 props 없이 기본 지도만 표시할 수 있다.

검증: `npm.cmd run build`, `npm.cmd run lint` 통과. 실제 카카오 지도 이벤트·주소 API와 모바일 조작은 브라우저 검증 전이다.

메인 화면 확인 항목:

- [ ] 출발·도착 선택 시 안내 문구와 중앙 마커 색상이 변경된다.
- [ ] 지도를 움직이거나 확대·축소하면 후보 주소가 지워지고 확정 버튼이 비활성화된다.
- [ ] 지도 이동 종료 후 조회한 주소가 표시되고 확정할 수 있다.
- [ ] 검색 결과 선택 후에도 중심 주소가 갱신되며 같은 결과 재선택도 동작한다.
- [ ] 빠른 지도 이동·대상 변경·취소 후 오래된 주소 응답이 반영되지 않는다.
- [ ] 실패·시간 초과 후 지도 이동으로 다시 조회할 수 있다.
- [ ] 확정 시 카드와 지도 마커가 갱신되고 취소 시 기존 위치가 유지된다.

이 절이 최신 구현 상태이며 앞선 절의 준비 중·다음 단계 설명은 각 작업 당시 기록이다.

### 확정된 출발·도착 주소 강조

`components/location/LocationCard.tsx`에서 `locations[type]`의 존재 여부에 따라 주소 표시 스타일을 구분한다. 확정된 주소에는 `text-black`과 `font-medium`을 적용하고, 설정 전 “장소 또는 주소 검색” 안내에는 기존 `text-[#86998C]`를 유지한다. 출발지와 도착지 각각의 확정 상태에 따라 독립적으로 적용된다.

## 실행 및 확인 방법

1. 프로젝트 루트의 `.env.local`에 `VITE_KAKAO_MAP_KEY`를 설정한다.
2. 카카오 개발자 설정에 개발 서버의 도메인을 등록한다.
3. `npm run dev`를 실행한다. 환경변수를 바꿨다면 서버를 재시작한다.
4. 터미널에 표시된 개발 서버 주소에 `/example`을 붙여 접속한다.
5. 지도 선택과 검색 선택을 출발지·도착지에 각각 시도한다.

## 검증 현황 및 남은 작업

예제 구현 후 `npm run build`와 `npm run lint`는 통과했다. 실제 브라우저에서 카카오 지도·검색 API의 정상 동작과 모바일 사용성은 아직 확인하지 않았다.

### 브라우저 검증 항목

- [ ] 출발·도착 선택 시 카드 강조, 안내 문구, 마커 색상이 일치한다.
- [ ] 지도를 움직이는 즉시 하단 문구가 변경되고 설정 버튼이 비활성화된다.
- [ ] 주소 조회가 완료된 뒤에만 위치를 확정할 수 있다.
- [ ] 검색창 포커스 표시와 검색 결과 개수·목록이 정상적으로 보인다.
- [ ] 주소와 장소 이름을 각각 검색하고 결과를 선택할 수 있다.
- [ ] 선택 결과가 검색창, 지도 중심, 하단 주소에 올바르게 반영된다.
- [ ] 검색 후 지도를 다시 움직여 위치를 조정할 수 있다.
- [ ] 확정 시 해당 카드만 갱신되고 취소 시 기존 주소가 유지된다.
- [ ] 빠른 지도 이동·재검색·선택 대상 변경 시 오래된 응답이 반영되지 않는다.
- [ ] 검색 결과 없음, 네트워크 실패, 시간 초과 상황을 확인한다.
- [ ] 모바일 키보드가 열린 상태에서 검색과 결과 선택이 가능하다.

### 후속 작업

- [ ] 고정 높이·비율의 지도 대신 남은 공간을 채우는 레이아웃 적용 검토
- [ ] 작은 화면에서 카드·검색 결과·확정 버튼의 배치와 스크롤 검증
- [ ] 검증한 예제 흐름을 메인 화면에 적용
- [ ] 현재 위치 기본 설정 및 수동 출발지 선택 정책 확정
- [ ] 확정한 좌표를 백엔드 경로 요청과 연결

현재 예제 지도는 `h-[50dvh] min-h-72`를 사용한다. 카드와 검색 결과 높이가 더해져 세로 스크롤이 생길 수 있으며, 한 화면 안에 맞추는 레이아웃은 아직 적용하지 않았다.
